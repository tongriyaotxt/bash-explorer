# xg.exe 被杀软误报 —— 事件记录与处置

## 1. 事件

| 项目 | 值 |
|---|---|
| 时间 | 2026-11-10 19:24:25 / 19:25:35（两次） |
| 检测名 | `Trojan:Win32/Bearfoos.A!ml`（`!ml` = 机器学习启发式，非特征码命中） |
| ThreatID | 2147731250，严重度 5（严重） |
| 检测来源 | 本地计算机 / 快速路径 / 系统 |
| 命中文件 | `D:\项目\闲扯\explorer-bash\xs\xg.exe`（99328 字节，2026-10-26 22:57 构建） |
| 引擎/签名 | AM 1.1.26100.4，AV 1.463.204.0（2026-11-09 更新） |
| 后果 | 文件被加"病毒"标记：读取被拒（`ERROR_VIRUS_INFECTED 0x800700E1`），`Get-FileHash` / `certutil` / 启动均被拦 |

同一条 ThreatID 在 2026-10-27 还命中了 `线束检测软件` 项目里的 `launcher.exe` / `injector32.exe`，
说明这条规则对本机自编译的小体积 .NET 产物一贯敏感，不是 xg 独有的问题。

## 2. 判定：误报（有证据）

1. **同源重建干净**：用完全相同的 `xg.cs` + 相同引用、相同 csc，重建出同样 99328 字节的
   `v0.exe`，`MpCmdRun -Scan` 报 `found no threats`，`--selftest` 46 项全过。
   代码没变、体积没变 → 命中的是"这一份二进制"的统计特征，不是代码行为。
2. **旧版干净**：2026-10-21 构建的 `xg.exe.bak`（82944 字节）扫描同样干净。
3. **代码本身无恶意面**：`xg.cs` 是 Shell 命名空间图形浏览器，只做
   `Shell.Application` COM 调用、`shgetfileinfo` 取系统图标、ListView 消息、DPI 设置。
   没有网络请求、没有远程加载、没有注入、没有注册表自启、没有加密/混淆。

## 3. 为什么会被 ML 盯上

裸 `csc /target:winexe` 产物同时具备几个高危统计特征：

- **无 Authenticode 签名**
- **无版本资源**：CompanyName / ProductName / FileDescription 全空，`FileVersion 0.0.0.0`
- **无应用清单**：没有 `requestedExecutionLevel`，系统按最保守兼容模式对待
- **无图标**（资源节几乎是空的）
- 代码里存在真实高危词面：`Process.Start("cmd.exe", "/k cd /d ...")`、
  `InvokeVerb("delete")`、`Directory.Delete(path, true)`、`--run` 参数批量执行命令

前四条让它落进"未知高熵可执行体"桶，后一条给了它一个可解释的"像木马"的分数。

## 4. 已做的处置（本仓库已生效）

新增/修改文件：

| 文件 | 作用 |
|---|---|
| `xs/xg.manifest` | asInvoker + PerMonitorV2 DPI + longPathAware + Win10/11 supportedOS + UTF-8 ACP |
| `xs/xg.assembly.cs` | 完整程序集元数据（Title/Product/Company/Copyright/Version/GUID，v1.1.0.0） |
| `xs/xg.ico` | 16/32/48/64/256 五档 PNG 图标（11447 字节） |
| `build.ps1` | xg 编译追加 `/optimize+ /debug- /platform:anycpu /win32icon /win32manifest`，并在构建末尾自动跑 MpCmdRun 扫描 |

产物：`xs/xg.exe` 105472 字节，SHA256 `E2A0408BF74BD4E920692674A252EF4F2F12EF49F3D316C6CB9DE2E639C612B2`，
`FileDescription=xg / ProductName=xg shell browser / CompanyName=YG / FileVersion=1.1.0.0`。

验证：

- `MpCmdRun -Scan -ScanType 3 -File xs\xg.exe` → `found no threats`
- 整个 `xs\` 目录扫描 → `found no threats`
- `xg.exe --selftest` 连跑 2 轮，每轮 46 行结果全部正常，无 `EXCEPTION`
- `build.ps1 -Test` 在临时副本里跑通全流程：编码检查 → 编译（含 Defender 自扫干净）→ xs 冒烟 → xg 自检

## 5. 日常操作

### 5.1 重建（先关掉正在跑的 xg）

```powershell
Get-Process xg -ErrorAction SilentlyContinue | Stop-Process -Force
powershell -NoProfile -ExecutionPolicy Bypass -File D:\项目\闲扯\explorer-bash\build.ps1 -Test
```

`build.ps1` 现在会把 Defender 扫描结果直接打在构建日志里，出现"命中"就别部署。

### 5.2 清掉安全中心里的旧记录

`Windows 安全中心 → 病毒和威胁防护 → 保护历史记录 → 找到 Trojan:Win32/Bearfoos.A!ml → 删除/清除`
（历史记录只是日志，清掉不影响当前文件；文件已在 19:29 前被替换）

### 5.3 可选：本机排除项（需要管理员）

```powershell
# 管理员 PowerShell
Add-MpPreference -ExclusionPath "D:\项目\闲扯\explorer-bash"
```

只排除开发目录，别排除整个盘。排除项只是止疼：下次换个项目、换个路径还会遇到。

### 5.4 建议：上报误报（治本）

提交页：<https://www.microsoft.com/en-us/wdsi/filesubmission>
选 *Software developer* → 上传被判定的 `xg.exe` → 填检测名 `Trojan:Win32/Bearfoos.A!ml`
+ 说明"自研 .NET WinForms 文件管理器，无签名，疑似 ML 误报"。
一般 1–3 个工作日规则会修正。

### 5.5 想彻底不被扫（正规做法）

用代码签名证书签 `xg.exe`（EV/OV 都行）。本机没装 `signtool`，需要先装 Windows SDK：

```powershell
# 安装后可用
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /a xs\xg.exe
```

自签名证书（`New-SelfSignedCertificate -Type CodeSigningCert`）只能得到"未知发布者"，
对 ML 判分的帮助远小于真证书，不建议为这个场景折腾。

## 6. 万一再被误报，怎么定位

```powershell
# 1. 拿检测详情（含哈希、签名版本）
Get-WinEvent -LogName "Microsoft-Windows-Windows Defender/Operational" -MaxEvents 200 |
  Where-Object { $_.Id -in 1116,1117 -and $_.Message -match 'xg\.exe' } |
  Select-Object TimeCreated, Message | Format-List

# 2. 复现
& "$env:ProgramFiles\Windows Defender\MpCmdRun.exe" -Scan -ScanType 3 -File xs\xg.exe

# 3. 二分：逐项去掉 /win32icon、/win32manifest、AssemblyInfo，看哪一项改变判定，
#    同时看代码里 cmd.exe 字符串、InvokeVerb("delete") 这类词面是否被新规则加权。
```

判定依据优先级：运行时行为 > 网络流量 > 实际产物 > 源码。
本次三条全查：无外连、无注入、产物为 Shell 浏览器 → 误报。
